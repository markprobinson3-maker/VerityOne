SETUP · THE ON-RAMP

Bring Verity One home.

Six calm steps to a running local node: install from source, open the dashboard, start a project, wire your agents, and feed it what you know. No accounts to create, nothing to sign up for. Everything below runs on your own machine.

RUNS LOCALLY

A node on your machine at localhost:3100. Yours, offline-capable, no cloud required.

SOURCE INSTALL

Built from source — one line clones the repo and bootstraps the stack. Stable channel is 0.1.2.

AGENTS CONNECT

Local agents speak to it over MCP. The graph remembers across sessions and tools.

THE SEQUENCE · ONE TO SIX

  1. Install Verity One

    One line clones the repository and runs the local bootstrap — Postgres, migrations, your tenant, config files. It is a source install: you are building from the published commit, not unpacking a binary. When it finishes, it prints the command to start the node.

    $ curl -fsSL https://verityone.app/install.sh | bash

  2. Open the local dashboard

    Start the node, then visit the dashboard in your browser. This is your window into the graph — it lives on your machine, served by the node you just installed.

    → http://localhost:3100/dashboard

  3. Create or choose a project

    From the dashboard, name a project — a workspace, a codebase, a body of research. It is the frame your memories and sources hang on, and the scope your agents read from. Start with one; add more whenever you like.

  4. Connect your local agents

    Wire an on-machine agent to the local node over MCP. One command writes the connector config for your client. Supported clients today are codex and claude-desktop (plus a generic profile for everything else). Local MCP is the authority — what an agent writes here lands in the graph in real time.

    $ vo mcp install --client codex

  5. Add what you know

    Feed the graph the things worth keeping — notes, files, the decisions behind them. Save a memory from the dashboard, or let an agent record one as it works. Over time these become the truth your agents return to instead of guessing.

  6. Enable VO+ OPTIONAL

    VO+ is an optional web bridge — a way to carry your memory beyond the desk on demand, for agents that run off your machine. It does not replace the local node and it is not a second source of truth; the web connector simply mirrors what local already holds. Turn it on only when you want it.
