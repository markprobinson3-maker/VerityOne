PROTOCOL & DISCOVERY

How agents discover and connect

Verity One is discoverable from a single root. An agent fetches GET / to learn the available surfaces, reads the ontology to understand the graph it is talking to, and follows the descriptor and connect routes to wire itself up.

  • GET / — the discovery root: the entry point that enumerates the live surfaces.
  • /schema — the ontology: the node and edge types that structure the graph.
  • /.well-known/agent — the agent descriptor, advertised at the well-known path.
  • /connect — the connect route: how a client attaches to a node.
  • /toc — a table of contents over the available routes.

Machine readers should start at the /agents page, and can read the plain-text descriptors at /agents.md and /llms.txt.

AUTHENTICATION · OAUTH

The OAuth model

Web agents reach Verity One through an OAuth-bearer flow. Your local node acts as the authorization server, and the protected resource is the connector at verityone.app/mcp. Two scopes are issued: vo.read for reads against the synced mirror, and vo.write.intent for writes — which are queued as intents, not applied live.

The flow is described by the two live well-known documents:

  • /.well-known/oauth-authorization-server — the authorization server metadata.
  • /.well-known/oauth-protected-resource — the protected-resource metadata for verityone.app/mcp.
HOSTED REST API

A REST surface, not a transport

The /hosted-mcp/* routes are a hosted REST API, authenticated with a vop_REDACTED bearer token. Despite the path name, this is plain request/response REST — it is not an MCP transport. Use it when you want HTTP access to the hosted mirror without speaking the MCP protocol.

The authoritative MCP transport is the local stdio server wired by vo mcp install; the hosted REST API and the OAuth-bearer connector at verityone.app/mcp both speak to the synced mirror, not to local authority.

RELEASES & CHANNELS

Source-only, in beta

Verity One installs from source and is in beta. There is no packaged or signed binary, and no Homebrew or npm release — the installer clones the repo at a pinned commit and builds a local node on your machine.

The stable channel is canonical and recommended: pinned to an exact commit. The nightly channel is auto-published from main and served from download.verityone.app. The current version is read from the stable manifest — 0.1.2.

  • /download — install from source, with the current release state.
  • /start — the step-by-step onboarding ladder: install, connect, first recall.
RUNNING A NODE · OPERATORS

A local node on your machine

Once built, Verity One runs as a local PostgreSQL-backed node at localhost:3100 — the source of truth, kept close and private on your machine. On-machine agents read and write to it live over the stdio MCP server.

Operators get a local dashboard at localhost:3100/dashboard to inspect and operate the node.
