Hosted portal

/my — not live yet

The hosted portal is not live yet. This URL is reserved so that homepage and /start links resolve, but there is no sign-in here, no account, no hosted dashboard. Nothing on this page is a working feature.

The pieces that will eventually live here — Google sign-in, the tenant portal, the hosted audit surface, and the queued-intent inbox — are explicitly later-phase work. They depend on the full Verity One runtime (database, auth, workers), which this bootstrap deploy does not expose and will not pretend to expose.

What works today

Use these instead

Local dashboard
Runs on your own machine at http://127.0.0.1:3100/dashboard once you have installed Verity One. This is the interactive surface today — it is not on verityone.app, and your local node stays authoritative.
Install & update
download.verityone.app is the canonical install and update origin. The apex /download page remains a compatibility landing page, and the mirrored apex manifest is at /releases/stable.json.
Public site
verityone.app/ and verityone.app/start explain the product and the three onboarding paths. They are static pages; they do not require sign-in.

Why a placeholder

Honest route reservation

Every link from the homepage and /start to /my is intentional — /my is where the hosted portal will live when it ships. For this bootstrap PR the route is reserved with this holding page so that:

  • No public link 404s on verityone.app.
  • Visitors see the state named honestly, not a mystery blank page or a fake sign-in.
  • When the hosted portal PR lands, the route swap is a single file replacement — no copy on the homepage or /start has to change.
