Verity One runs locally on your machine — Postgres and a small API, kept close and private. One command builds it from source. Your local node is the source of truth; nothing about the install reaches past your desk unless you decide it should.

Verity One installs from source. The stable manifest is source-mode — there is no packaged or signed vo-cli binary, and no Homebrew or npm release yet. The installer clones the repo, pins it to the exact commit named in the manifest, and builds it on your machine. The apex verityone.app/download is a compatibility landing; the canonical install origin is download.verityone.app. Source install still works exactly as shown below, and source install remains a supported parallel path — not a fallback.

1.   ONE-LINE INSTALL 
COPY$ curl -fsSL https://verityone.app/install.sh | bash

The installer is served from the canonical install origin, download.verityone.app. It reads the live stable manifest, builds Verity One from source at the pinned commit, and starts your local node.

2.   CONNECT YOUR AGENTS 
COPY$ vo mcp install --client codex

This wires a client to your local node over a stdio MCP server — the authoritative transport. Valid clients today are codex, claude-desktop, and generic. Your agents then recall from the same local memory.

New to the whole flow? The step-by-step onboarding ladder lives at /start#shortest — install, connect, and first recall, in order — so this page stays a reference, not a duplicate of it.

PREFER TO BUILD IT YOURSELF?

The same source path is open by hand. Read the pinned commit from the canonical manifest, clone the repo, check out that exact ref, and build. Nothing here downloads a prebuilt binary — there isn't one. 

$ SHA=$(curl -fsSL https://download.verityone.app/releases/stable.json \
    | bun -e 'console.log(JSON.parse(await Bun.stdin.text()).install.source_ref)')

$ git clone https://github.com/markprobinson3-maker/VerityOne.git
$ cd verity-one
$ git checkout "$SHA"
$ bun install
$ bun run db:reset
$ cd api && bun run start
CANONICAL SURFACES
  • download.verityone.app — the canonical install origin and landing page.
  • releases/stable.json — the live stable manifest (channel, version, pinned source commit).
  • releases/stable.json.sig — a detached signature over the manifest, so the installer can verify the manifest's integrity before building.
  • install.sh — the one-line install script itself.
  • release notes — the published notes referenced by the stable manifest.
BEYOND THE DESK · OPTIONAL

VO+ is a web bridge that can carry your memory beyond the desk on demand — it does not replace the local node.

Everything above runs entirely local, and the local node stays the source of truth. If and when you want recall from web MCP agents across browsers, phones, and tablets, VO+ is the optional layer that reaches there. It is a bridge, not a requirement, and none of it is needed to install or run Verity One.
